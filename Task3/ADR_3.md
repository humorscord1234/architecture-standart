### <a name="_qmphm5d6rvi3"></a>**Решение**
 
[containers.puml](containers.puml)

1. Легкий найм разработчиков на популярные технологии
2. Все старые сервисы спрятаны за сервисами прокси для возможности создания новых сервисов и переключения трафика в новые версии систем
3. Фронтенд не агрегирует запросы с разных бэкендов, для этого сделаны бэкенды которые агрегируют все данные и веб приложению предоставляют аггреированный результат
4. Реализован новый сервис чтобы исключить работу с Excel и мигрировать данные в сервис депозитов
### <a name="_bjrr7veeh80c"></a>**Альтернативы**

1. Уменьшить кол-во прокси сервисов, и реализовать один прокси сервис
2. Уменьшить кол-во bff сервисов, и реализовать один bff

**Недостатки, ограничения, риски**

1. Потребуется найм новых разработчиков из-за увеличения количества разрабатываемых сервисов.
2. Потребуется переобучение сотрудников для работы с новыми системами.
3. Усложнение инфраструктуры
4. Потребуются специалисты SRE которые смогут прогаммировать инфраструктуру для реализации новой архитектуры
5. Разработка e2e тестов так как появляется много сервисов и нужно тестировать все взаимодествия постоянно
6. Реализация мониторинга, трасировки
